Overview

Dispatchers were juggling three separate tools to track a fleet of several hundred vehicles. Latency between an event happening and it showing up on screen could reach minutes — long enough for a missed delivery to become a customer complaint.

Helm replaces all of it with one console. Vehicle telemetry streams in over WebSockets, updates render in under a second, and every team sees exactly the slice of data their role needs — nothing more.

Key features

  • Live telemetry streamsHundreds of vehicles pushing position and status over WebSockets, rendered on a map with sub-second updates.
  • Role-based accessDispatchers, managers, and clients each get a tailored view, enforced from the API down to the UI.
  • Custom charting layerA purpose-built canvas charting engine that stays smooth while plotting thousands of live data points.
  • Incident timelineEvery alert is captured, replayable, and exportable — turning chaos into an auditable record.

The challenge

The hard part wasn't the data — it was keeping the interface calm and fast while thousands of updates poured in every minute. I built a batching layer that coalesces incoming events into animation-frame-aligned renders, so the UI never thrashes.

On the backend, a Go service fans out updates through Redis pub/sub, letting the system scale horizontally without dropping a single connection.
